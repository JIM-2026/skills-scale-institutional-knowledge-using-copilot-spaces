# OctoAcme — プロジェクト管理文書 README

このREADMEは `docs/` 配下に置かれたOctoAcmeのプロジェクト管理に関する公式ドキュメント群への入り口です。各ドキュメントは、プロジェクトのライフサイクル（立ち上げ、計画、実行、リリース、振り返り、リスク管理など）に対応したガイダンスを提供します。

## OctoAcmeプロジェクト管理プロセスの概要

OctoAcmeのプロジェクト管理は、**顧客価値の優先**、**反復的な成果物の提供**、**明確な所有責任**、**データ駆動型の意思決定**の4つの原則に基づいています。プロジェクトのライフサイクルは5つの段階で構成されています：

1. **イニシエーション**では、問題定義、ステークホルダー特定、高レベルのタイムラインを確定し、ワンページャーと実現可能性を検証します。
2. **計画**では、作業を出荷可能なインクリメントに分解し、受け入れ基準を定義し、依存関係とリスクを特定します。
3. **実行**では、日次スタンドアップと週次デリバリー同期を通じて、進捗追跡とブロッカー解決に注力します。
4. **リリース**では、品質確認とセキュリティスキャンを経た上で、段階的なデプロイメントを実施します。
5. **クローズと振り返り**では、教訓を捉え、継続的改善アクションアイテムに変換します。

### 主要なワークフローと役割分担

実行における主要なワークフローはGitHub Projectsのプロジェクトボード（バックログ、準備完了、進行中、レビュー待ち、QA、完了）を軸に展開されます。プルリクエスト戦略では400行以下の小さなPRを推奨し、自動テスト、リント、セキュリティスキャンをCI/CDで実施した上で、最低1つ以上のレビュー承認を必須としています。

プロジェクトチームは明確に分断された役割で構成されています：

- **プロジェクトマネージャー（PM）**は納期、リスク、コミュニケーションを調整します
- **プロダクトマネージャー（PdM）**は成果物と優先順位を定義して成功を測定します
- **開発者**はテストとドキュメンテーション責任を含めて機能を実装します
- **QA/テスト**は受け入れ基準の検証を担当します

週次PM・PdM同期、週2回の配信チームスタンドアップ、月次ステークホルダー更新といったコミュニケーション体制により、情報流通と透明性が確保されます。

### 品質保証と継続的改善

品質保証はプロセスに統合された多層構造として機能します。新規ロジックには単体テストを、該当する場合は統合テストを実装し、本番リリース前に重要フローの端から端までのスモークテストを実行します。セキュリティスキャンはCI/CDパイプラインに組み込まれ、必要に応じて手動QAによる機能受け入れも実施されます。

リスク管理は**リスク登録簿**（ID、説明、インパクト、尤度、所有者、緩和計画、ステータス）を通じて体系化され、週次同期で定期レビューが行われます。スプリント後、リリース後、重要マイルストーン後には**回顧会**（45～75分、匿名アイデアボード活用）を実施し、「うまくいったこと」「改善できること」「アクションアイテム」を捉えます。これらの改善提案はプロジェクトバックログまたはイシューとして記録され、週次PM同期で進捗追跡されることで、組織的な学習と継続的改善の文化が実現されます。
